# 취업지원실 도서 나눔 행사 배포 안내

## 조회 성능 개선 버전 적용

1. `apps-script/career-book-giveaway/Code.gs`를 연결된 Apps Script에 반영합니다.
2. 편집기에서 `setupCareerBookGiveawaySheets`를 한 번 실행해 필수 시트와 수령캠퍼스 열을 준비합니다. 이제 일반 조회·신청 요청에서는 시트 생성과 열 추가를 실행하지 않습니다.
3. 기존 웹 앱 배포를 새 버전으로 업데이트합니다. 기존 URL을 유지하면 HTML의 URL 수정은 필요 없습니다.
4. `public/assets/js/app.js`를 정적 사이트에 배포합니다.

첫 진입은 로딩창과 스피너를 표시하고, 정적 도서 JSON과 최초 신청현황 조회가 끝난 뒤 목록을 표시합니다. 신청현황 조회가 실패하면 로딩을 종료하고 오류를 안내하며, 5초·10초 후 최대 두 번 자동 재시도합니다. 최근 2분 이내 캐시가 있으면 최근 상태를 유지하고, 확인된 정보가 없으면 신청 버튼을 비활성화합니다. 수동 새로고침도 가능합니다.

첫 화면의 저장된 표지·소개 조회는 신청현황 조회와 병행합니다. 신청현황 확인 뒤 표지 정보는 추가로 최대 2초, 첫 6권의 이미지 사전 로딩은 최대 1.2초만 기다립니다. 실제 표지가 없는 도서는 기본 표지를 표시하며, 느린 응답은 뒤늦게 반영될 수 있습니다. 받은 메타데이터는 도서 검색기준과 서버 주소를 확인해 브라우저에 최대 150권·6시간 저장하여 다음 방문에 재사용합니다. 빈 결과는 영구 저장하지 않습니다. 설정 조회는 주요 화면 로딩 후 시작합니다.

신청 진행상황 조회는 동시에 여러 번 실행하지 않으며, 일시적인 오류 시 1초 후 한 번 재조회합니다(각 조회 최대 20초). 마지막까지 실패해도 이미 확인한 신청내역은 유지합니다. 별도 개인정보 캐시는 추가하지 않습니다.

목록·상세 화면을 열어두면 1분마다 신청현황을 갱신하고, 다른 탭에서 돌아왔을 때 1분 이상 지난 상태도 갱신합니다. 동시에 시작한 조회는 합쳐서 처리합니다. 신청현황 조회는 `refresh=1`로 서버의 표시용 캐시를 건너뜁니다. 신청·취소 성공 시 해당 도서와 권수를 즉시 반영한 뒤 서버에서 다시 확인하며, 변경 전에 시작한 오래된 응답은 무시합니다. 최종 신청 가능 여부는 서버의 최신 데이터로 판단합니다. 이 신청상태 표시 개선은 프런트엔드만 배포하면 적용되며 Apps Script 변경은 필요 없습니다.

정상 신청상태 조회 및 주기적 갱신 안내는 숨기며, 최초 확인 중이거나 조회에 실패한 경우에만 안내를 표시합니다.

정적 JSON은 `no-cache`로 변경 여부를 확인합니다. 일반 조회는 15초, 로그인·신청 응답은 30초까지 기다립니다. 취소는 15초 내 응답을 받지 못하거나 연결이 끊기면 본인 신청내역을 최대 두 번(각 10초 제한, 사이 1.5초 대기) 조회해 해당 신청ID가 `취소`인지 확인합니다. 쓰기 요청은 자동 재전송하지 않습니다. 확인된 취소는 화면에 즉시 반영하고 로딩을 종료하며, 추가 전체 조회를 기다리지 않습니다. 끝내 확인하지 못하면 신청내역 새로고침을 안내합니다. 일괄 취소 도중 일부만 성공해도 확인된 결과는 유지합니다. 이 변경은 프런트엔드 배포만 필요합니다.

이용자 화면에서는 알라딘을 실시간 조회하지 않습니다. 아래 사전 수집 절차를 적용해주세요. 아직 수집되지 않은 책은 제목 표지와 소개 준비 안내를 표시합니다. 저장 정보 일괄 조회가 실패해도 개별 알라딘 조회로 재시도하지 않습니다.

1~4권 신청은 매 실행마다 도서ID 한 열로 인덱스를 만들고 선택된 행만 읽습니다. 시트 정렬·행 추가 후에도 이전 행 번호를 재사용하지 않습니다. 5권 이상은 원격 호출 횟수를 줄이기 위해 일괄 읽습니다. 신청중 여부는 표시용 캐시를 사용하지 않고 잠금 안에서 최신 도서ID·상태 열로 확인합니다. 신청과 취소는 공용 잠금을 사용합니다.

로컬 회귀 검증: `npm test` (Windows PowerShell에서 실행 정책 오류가 나면 `npm.cmd test`). 실제 Apps Script 지연과 알라딘 응답시간은 배포 후 측정해야 합니다. 첨부 엑셀 수식과 운영 데이터는 변경하지 않습니다.

## 표지·소개 사전 수집과 정적 배포

권장 흐름: **알라딘 → 관리자 수집 → 구글시트 `도서메타` → 정적 JSON → 이용자 화면**. 신청현황·로그인·신청·취소는 계속 Apps Script를 사용합니다. 표지 URL을 저장하므로 실제 이미지 파일은 알라딘 이미지 서버에서 내려받습니다.

### 1단계: 구글시트에 저장

1. 새 `Code.gs`를 Apps Script에 붙여 넣고 `setupCareerBookGiveawaySheets`를 실행합니다. 기존 도서/신청 열은 유지하고 `도서메타` 시트를 추가합니다.
2. **`syncAllBookMetadata`를 한 번 실행합니다.** 이미 수집된 도서를 건너뛰고 전체 미처리 도서를 연속 수집합니다. 내부적으로 12권씩 저장하지만 12권에서 멈추거나 배치 사이에 10분을 기다리지 않습니다. `도서메타`에서 표지URL·소개·알라딘서명·ISBN13·수집상태를 확인합니다.
3. 한 실행이 3분에 도달하면 결과를 저장하고 최소 1분 뒤 자동으로 이어서 수집합니다. 별도 트리거 설치는 필요 없고 기존 10분 간격 수집 트리거도 자동 제거합니다. 하루 예산을 다 쓰면 한국시간 다음 날 00:05 이후 이어서 수집합니다. 오류 재시도를 기다리는 도서만 남으면 재시도 가능 시각에 이어서 처리합니다. 전체가 `완료` 또는 `미검색`이면 자동 종료하며 실행 로그에 전체 수집 완료를 표시합니다. 중지하려면 **`stopAllBookMetadataSync`**를 실행합니다. 현재 진행 중인 묶음은 저장될 수 있습니다.
4. **기존 웹 앱 배포를 새 버전으로 업데이트한 뒤** 변경된 `public` 폴더를 배포합니다. 새 프런트엔드는 `savedBookMetaBatch`를 사용하므로 구버전 서버에서는 표지 대신 기본 표지가 표시됩니다.

같은 ISBN·서명·저자는 조회를 재사용합니다. `완료`와 `미검색`은 자동으로 다시 수집하지 않고, 통신/API 오류는 `오류`로 기록해 24시간 뒤 재시도합니다. 원본 ISBN·서명·저자가 바뀌면 다시 수집합니다. 같은 검색기준으로 강제 재수집하려면 해당 검색기준의 행을 모두 `도서메타`에서 삭제하고 수집합니다. 6시간 캐시가 남아 있으면 재사용될 수 있습니다.

기본 예산은 하루 4,000회입니다. 이제 실제 외부 요청을 보내기 직전에 요청 수만큼 계산하며, 캐시나 저장값 재사용은 예산을 사용하지 않습니다. 같은 키를 쓰는 다른 프로그램의 호출은 이 예산에 포함되지 않습니다. [알라딘 공식 안내](https://blog.aladin.co.kr/openapi/6695306)의 기본 한도는 하루 5,000회입니다. 한 번 실행으로 전체 수집을 시작하지만 호출 한도와 응답 속도에 따라 완료에는 여러 날이 걸릴 수 있습니다. [Apps Script의 실행당 6분 제한](https://developers.google.com/apps-script/guides/services/quotas)에 대비해 실행별 3분의 공통 작업 예산을 적용합니다. 이미 시작된 외부 호출의 응답시간까지 강제로 제한하는 기능은 아닙니다. 시간/예산 부족으로 마치지 못한 검색은 오류로 기록하지 않고 다음 실행에서 이어서 조회합니다.

전체 수집은 시작 시점에 읽은 도서목록을 기준으로 하며 수집 도중 목록을 추가했다면 완료 후 `syncAllBookMetadata`를 다시 실행하세요. 일반 조회·신청·취소의 잠금은 점유하지 않습니다. 예상치 못한 실행 종료에 대비한 후속 트리거를 작업 전에 예약하고, 시트/서비스 예외가 발생하면 1시간 뒤 재시도합니다. Google 계정의 권한 취소나 플랫폼의 일일 실행 한도까지 우회하는 기능은 아닙니다. 운영 확인용 `syncBookMetadata`는 기존처럼 12권만 처리하며, `installBookMetadataTrigger`/`removeBookMetadataTrigger`는 기존 10분 주기 방식에만 사용합니다. 전체 수집 중에는 별도로 실행하지 마세요. 수집·내보내기 함수는 Apps Script 편집기에서만 실행하며 공개 웹 요청에는 노출하지 않습니다.

현재 정적 목록의 ISBN은 비어 있어 제목 검색 결과를 사용합니다. 판본·권차가 다른 책이 매칭될 수 있으므로 ISBN을 보완하거나 저장된 알라딘서명·표지를 검수해주세요. 알라딘에서 찾은 ISBN은 원본 도서목록에 자동 덮어쓰지 않습니다.

### 2단계: 사이트에 함께 배포 — 표지 조회 속도 권장 설정

1. `exportBookMetadata`를 실행합니다. 실행 로그의 Google Drive 링크에서 `book-metadata.json`을 다운로드합니다. 이 파일에는 도서 메타데이터만 포함되며 신청자 정보와 API 키는 포함되지 않습니다. Drive 공유 설정은 변경하지 않습니다.
2. 저장소 폴더에서 실행합니다.

   ```powershell
   node scripts/import-book-metadata.cjs "C:\다운로드경로\book-metadata.json"
   ```

3. 수정된 `public/assets/data/career-books.json`과 프런트엔드를 배포합니다. 원본 도서ID·ISBN·서명·저자가 일치하는 결과만 반영합니다. `미검색`도 반영해 불필요한 조회를 생략합니다. 일부만 수집된 파일도 사용할 수 있습니다.
4. 이후 수집 결과를 갱신하면 다시 내보내기·가져오기·배포합니다. `npm run build:data`로 목록을 재생성한 경우에도 메타데이터를 다시 가져옵니다.

정적 JSON에 포함된 표지·소개는 Apps Script에 요청하지 않습니다. 아직 포함되지 않은 도서는 화면에 표시되는 최대 25권 단위로 `도서메타`의 저장값을 읽습니다. 한 페이지 세션에서 같은 도서의 동시 조회와 빈 결과를 재사용하며, 조회 실패 후 1분간 추가 메타데이터 요청을 쉬도록 했습니다. 저장값을 갱신한 뒤 확인하려면 페이지를 새로고침해주세요.

첨부 엑셀의 내용은 데이터로만 사용합니다. 운영 지시사항은 이 문서와 사용자 요청을 기준으로 합니다.

## 1. 구글시트 만들기

1. `outputs/career-book-giveaway/dong-a-career-book-giveaway-google-sheets-template.xlsx` 파일을 Google Drive에 업로드합니다.
2. 업로드한 파일을 Google Sheets로 엽니다.
3. 시트는 `도서목록`, `신청현황`, `이용자`, `설정` 4개로 구성되어 있습니다.
4. `도서목록`의 `ISBN13` 열을 채우면 알라딘 표지와 소개 매칭 정확도가 좋아집니다.

## 2. Apps Script 연결

1. 구글시트에서 `확장 프로그램 > Apps Script`를 엽니다.
2. `apps-script/career-book-giveaway/Code.gs` 내용을 붙여 넣습니다.
3. Script Properties에 아래 값을 저장합니다.
   - `ALADIN_TTB_KEY`: 보유 중인 알라딘 Open API TTBKey
   - `SPREADSHEET_ID`: 신청을 받을 구글시트 주소의 `/d/`와 `/edit` 사이에 있는 긴 ID입니다. 같은 시트에 바인딩된 Apps Script라면 생략 가능하지만, 배포 오류를 줄이려면 등록하는 것을 권장합니다.
     - 예: `https://docs.google.com/spreadsheets/d/구글시트ID/edit#gid=0` 주소에서 `구글시트ID` 부분만 입력합니다.
     - `https://script.google.com/macros/library/d/...` 주소의 ID는 Apps Script 라이브러리 ID라서 `SPREADSHEET_ID`로 쓰면 안 됩니다.
     - `1AbCdEfGhijk12345XYZ` 같은 예시 값이 남아 있으면 반드시 실제 구글시트 ID로 바꿉니다.
4. Apps Script 편집기 상단 함수 선택 목록에서 `setupCareerBookGiveawaySheets`를 선택하고 `실행`을 눌러 권한을 승인합니다.
   - 첫 실행 때 권한 승인 창이 나오면 Google 계정을 선택합니다.
   - "이 앱은 Google에서 확인하지 않았습니다" 화면이 나오면 `고급 > 프로젝트로 이동 > 허용` 순서로 승인합니다.
   - 실행 후 구글시트에 `도서목록`, `신청현황`, `이용자`, `설정` 시트가 있는지 확인합니다.
5. 필요하면 함수 선택 목록에서 `setSpreadsheetId`, `setAladinTtbKey`를 각각 실행해 값을 대화상자에 입력할 수 있습니다.
6. `배포 > 새 배포 > 웹 앱`을 선택합니다.
7. 실행 권한은 본인, 접근 권한은 행사 운영 방식에 맞게 설정합니다.
8. 배포 후 웹 앱 URL을 복사합니다.

## 3. 웹사이트와 연결

`public` 폴더 안의 각 HTML 파일 상단에 있는 `appsScriptUrl` 값을 Apps Script 웹 앱 URL로 바꿉니다.

```html
window.CAREER_BOOKS_CONFIG = {
  appsScriptUrl: "https://script.google.com/macros/s/배포ID/exec",
  dataUrl: "assets/data/career-books.json"
};
```

## 운영 메모

### 기존 플랫폼에 수령 캠퍼스 기능 적용

1. 연결된 Google Sheets의 Apps Script에서 `apps-script/career-book-giveaway/Code.gs` 전체 내용으로 기존 코드를 교체하고 저장합니다.
2. `setupCareerBookGiveawaySheets`를 실행합니다. 기존 A~Q열과 신청 기록은 유지하며, `신청현황` R1에 `수령캠퍼스`가 추가됩니다. 기존 신청의 캠퍼스는 빈칸으로 유지됩니다. R열에 다른 데이터가 있으면 덮어쓰지 않고 오류로 알립니다.
3. 기존 웹 앱 배포를 새 코드 버전으로 업데이트합니다. 기존 웹 앱 URL을 유지하면 사이트의 URL 설정을 바꿀 필요가 없습니다.
4. 수정된 `public/assets/js/app.js`와 `public/assets/css/styles.css`를 웹사이트에 반영합니다.
5. 개별 도서 또는 장바구니에서 신청할 때 캠퍼스를 선택하지 않으면 제출되지 않는지 확인합니다. 두 선택지 각각으로 신청하여 R열에 `한림도서관(승학)` 또는 `부민도서관(부민)`이 저장되는지 확인합니다.

장바구니로 여러 권을 신청하면 선택한 캠퍼스가 모든 신청 행에 저장됩니다. 본인 신청 내역에도 수령 캠퍼스가 표시되며, 과거 신청은 `미지정`으로 표시됩니다. 첨부 엑셀을 운영 시트에 다시 업로드할 필요는 없습니다. 기존 업로드용 템플릿에도 설정 함수를 실행하면 열이 추가되며, 템플릿 생성 코드는 새 열을 포함하도록 수정되어 있습니다.

- `신청현황`의 상태는 `신청접수`, `처리중`, `확정`, `취소`, `중복`, `마감` 중 하나로 관리합니다.
- `신청접수`, `처리중`, `확정` 상태인 도서는 사이트에서 신청 진행중으로 표시됩니다.
- 알라딘 API 키는 웹페이지에 넣지 말고 Apps Script의 Script Properties에만 저장하세요.
- 웹사이트는 정적 파일이라 GitHub Pages에서 동작하고, 신청 처리와 알라딘 API 호출은 Apps Script가 중계합니다.
